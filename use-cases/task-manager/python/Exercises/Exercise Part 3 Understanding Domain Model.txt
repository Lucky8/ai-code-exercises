- Glossary: 
Task:	A piece of work that needs to be tracked. It has a title, description, priority, status, dates, tags, and a unique ID.

Task ID:	A unique UUID assigned to each task. It allows users and the application to identify a specific task.

Title:	The short name of the work item. It is required when creating a task.

Description:	Optional additional detail explaining what the task involves.

Priority:	The relative importance or urgency of a task. It can be LOW, MEDIUM, HIGH, or URGENT.

Low priority:	Work with relatively little urgency or business impact. Represented by the value 1.

Medium priority:	The default level of importance. Represented by the value 2.

High priority:	Important work that should receive attention soon. Represented by the value 3.

Urgent priority:	Work requiring immediate or near-immediate attention. Represented by the value 4.

Status:	The current stage of a task in its workflow. It can be TODO, IN_PROGRESS, REVIEW, or DONE.

TODO:	A task that has been created but work has not started.

IN_PROGRESS:	A task currently being worked on.

REVIEW:	A task whose work is ready to be checked, approved, or evaluated.

DONE:	A completed task. When a task reaches this status, its completion time is recorded.

Workflow:	The progression of a task through statuses, conceptually: TODO -> IN_PROGRESS -> REVIEW -> DONE.

Due date:	The deadline by which a task should be completed. It is optional.

Overdue:	A derived state meaning the due date has passed and the task is not DONE. It is calculated by is_overdue() rather than stored directly.

Completed date:	The timestamp recorded when a task is marked as DONE. In the code, this is completed_at.

Created date:	The timestamp recording when the task was first created.

Updated date:	The timestamp recording the most recent modification to the task.

Tag:	A flexible label used to categorize a task, such as bug, documentation, or onboarding. A task can have multiple tags.

Task collection:	The set of tasks currently held by TaskStorage. Internally, tasks are kept in a dictionary indexed by task ID.

Task storage:	The component responsible for loading, saving, finding, updating, and deleting tasks.

Persistence:	Keeping tasks available after the program exits. This application persists them in a local tasks.json file.

JSON:	The file format used for task persistence. Tasks are converted to JSON when saved and reconstructed when loaded.

Encoder:	TaskEncoder converts Task objects, enums, and date values into JSON-compatible data.

Decoder:	TaskDecoder reconstructs Task objects from JSON data.

Enum:	A fixed collection of allowed values. TaskPriority and TaskStatus are both enums.

Task manager:	The application/service layer represented by the TaskManager class. It coordinates task operations between the CLI, domain model, and storage.

CLI:	Command-line interface. It allows users to create, list, update, inspect, tag, delete, and report on tasks.

Filter:	A restriction used when listing tasks, such as status, priority, or overdue state.

Statistics:	Summary information calculated from the task collection, including total tasks, counts by status and priority, overdue tasks, and tasks completed in the previous seven days.

Repository-like storage:	A design role played by TaskStorage: it hides the details of how tasks are stored and provides methods for retrieving and changing them.
