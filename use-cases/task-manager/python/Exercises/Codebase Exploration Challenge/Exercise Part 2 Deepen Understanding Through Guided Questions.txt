Q - In create_task(), what happens to priority_value, due_date_str, and tags before a Task object is created?

A - The numeric priority is converted into a TaskPriority enum, such as 3 becoming TaskPriority.HIGH.

Q - Why do you think update_task_status() handles DONE differently from statuses such as IN_PROGRESS or REVIEW?
Look closely at which model method is called and which timestamps change.

A - DONE is handled differently because completion has side effects beyond changing status.



Q - If a task ID does not exist, what does each update method return?
Compare update_task_status(), update_task_priority(), and update_task_due_date().

A - update_task_priority() returns False, because storage.update_task() cannot find the task.
update_task_due_date() returns False for a nonexistent task. It also returns False for an invalid date.
update_task_status() returns False for nonexistent tasks when the new status is not DONE.
update_task_status() returns None when the new status is DONE and the task does not exist, because that branch has no final return False.


Q - In list_tasks(), what happens when both show_overdue and status_filter are provided?
What does the order of the if statements tell you about which filter takes precedence?

A - show_overdue takes precedence:
If both show_overdue=True and a status filter are provided, only overdue tasks are returned. The status filter is ignored.

The first matching condition returns immediately, so the order of these checks defines the filter precedence.


Q - Why does get_statistics() retrieve all tasks from storage rather than calculate statistics inside TaskStorage?
Share the get_statistics() method and identify which calculations are domain-related versus persistence-related.

A - get_statistics() retrieves all tasks from storage because storage’s responsibility is retrieving data, while calculating business summaries belongs in the application layer.
The overdue rule itself belongs to the Task model through is_overdue(), while app.py aggregates the results.

This separation keeps TaskStorage focused on loading, saving, retrieving, updating, and deleting tasks rather than embedding reporting rules inside the persistence layer.
